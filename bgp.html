BGP path attributes // RFC 4271

BGP is a TCP application with a tiny fixed header and a large, flag-driven type-length-value space. The four high bits of each attribute flag octet decide whether a speaker must understand it, whether it survives a hop, and how long the length field is.

01Message & UPDATE layout

marker · length · type

Every BGP message starts with a 16-byte Marker (all ones in BGP-4), a 16-bit Length including the header, and an 8-bit Type. The default maximum length is 4096 bytes; RFC 8654 adds an extended message capability for larger updates.

UPDATE is three variable regions

Withdrawn Routes Length (2 bytes) scopes the withdrawn prefix list. Total Path Attribute Length (2 bytes) scopes the attribute list. Whatever remains after those regions is NLRI. An empty UPDATE with no withdrawn routes and no attributes is a valid keepalive-like advertisement of nothing.

02Attribute flags

one octet that changes everything

The first octet of every path attribute is a flag field. Optional means a speaker that does not understand the attribute may ignore it. Transitive means the attribute should be passed on. Partial marks an optional transitive attribute that a speaker did not fully understand. Extended Length switches the length field from one byte to two.

The low four bits are reserved and must be zero. Partial is only meaningful for optional transitive attributes; for well-known attributes it must be clear. Extended Length may be set even when the value is short, but it is unusual.

Attribute header · normal length

Attribute header · extended length

AS_PATH segment

AS_PATH is a list of segments. The segment length counts AS numbers, not bytes, so the total byte length depends on the negotiated AS width.

COMMUNITIES value layout

Standard communities are two 16-bit halves: an AS number and a local value. Extended communities add a type and subtype; large communities use three 32-bit words.

the flags must match the type

Well-known attributes have Optional=0 and Transitive=1. Optional non-transitive attributes have Optional=1 and Transitive=0. Optional transitive attributes have both. A Partial bit on a well-known attribute is a protocol error under RFC 4271; RFC 7606 tightened the handling of malformed attributes.

06Wire notes

where BGP parsers and routers disagree
AS width is context, not metadata

AS_PATH carries a sequence of AS numbers but no width byte. A session that negotiated four-octet AS support uses 4-byte ASNs; an old session uses 2-byte ASNs and may carry AS4_PATH alongside. Parsing with the wrong width silently shifts every subsequent segment.

  • Marker is all ones. BGP-4 expects 16 bytes of 0xff. Authentication mechanisms historically changed it; modern BGP uses TCP-MD5/TCP-AO at the transport layer.
  • Length includes the 19-byte header. The default maximum message size is 4096 bytes; extended messages (RFC 8654) can reach 65535 with capability negotiation.
  • Attribute length is bytes, not elements. Communities are 4 bytes each; extended communities 8; large communities 12. A length not divisible by the element size is a parse error.
  • Segment length is AS count. For AS_PATH, the second byte of a segment counts ASNs, not bytes. Multiply by the AS width when walking the value.
  • Partial means “I did not understand this”. It is only valid on optional transitive attributes and should make the receiver forward the attribute even though it ignored the semantics.
  • RFC 7606 changed error handling. Many malformed attributes are now treated as withdraw-with-error rather than session reset. Do not assume an old “treat-as-withdraw” path.
  • Path attributes are policy, not truth. ORIGIN, AS_PATH, MED and communities are inputs to decision processes; RPKI and route-leak detection live outside the attribute encoding.
