IPsec // AH, ESP & IKEv2

IPsec protects IP packets at the network layer. AH authenticates the packet and the outer IP header; ESP encrypts and authenticates the payload. IKEv2 negotiates the security associations. This page distinguishes the fields observable in a capture from those available only to the endpoints after decryption.

01Authentication Header

protocol 51 · integrity, no confidentiality

AH authenticates the immutable parts of the IP header, the AH header and the payload. It does not encrypt. The Payload Length counts the AH header in 32-bit words minus two, and the ICV length depends on the negotiated algorithm (often 12 or 16 bytes).

AH and NAT do not mix

AH covers the outer IP addresses. A NAT rewrites them, so the ICV no longer verifies. This is why NAT traversal uses ESP and UDP encapsulation, not AH.

02Encapsulating Security Payload

protocol 50 · encryption + integrity

ESP starts with an 8-byte header and ends with a trailer and an ICV. Everything between them is ciphertext. In transport mode the original IP header stays outside; in tunnel mode a new outer IP header is added and the entire original packet is inside.

FieldVisibilityMeaning
SPIcleartextSecurity association identifier; the receiver uses it to select keys and algorithms
SequencecleartextAnti-replay counter; it is not encrypted
CiphertextopaqueEncrypted payload plus padding, pad length and next header
ICVopaque without keysIntegrity check value over the ESP packet; algorithm-specific length
The inner protocol type is not visible

The Next Header field is inside the encrypted trailer. Without keys, a capture shows only “ESP”. TCP or UDP must not be inferred from the outer packet.

03IKEv2 header

UDP 500 / 4500

IKEv2 is the control protocol that creates IPsec SAs. The header is 28 bytes and is followed by a chain of payloads. The initiator and responder SPIs are eight bytes each. The I flag marks the original initiator; the R flag marks a response.

ExchangeTypePurpose
IKE_SA_INIT34Negotiate algorithms, exchange nonces and Diffie-Hellman public values
IKE_AUTH35Authenticate identities and create the first child SA
CREATE_CHILD_SA36Create or rekey child SAs
INFORMATIONAL37Delete, notify, configure

06Wire notes

what a capture can establish
  • ESP conceals the inner packet. The SPI, sequence and outer addresses are visible. Ports, inner addresses and payload are not visible without keys.
  • AH authenticates more than ESP. AH covers outer IP fields; ESP does not. AH therefore breaks under NAT.
  • Transport mode vs tunnel mode. Transport mode keeps the original IP header; tunnel mode adds a new one. A capture may show either.
  • IKEv2 is not ESP. It runs over UDP 500, or 4500 when NAT traversal is in use. The first IKE_SA_INIT messages are unencrypted; later exchanges use SK payloads.
  • Sequence numbers are per SA. They provide anti-replay. A capture cannot tell whether a receiver accepted a replay without the SA state.
  • Algorithms are negotiated, not encoded in the packet. The SPI selects the SA; the SA holds the algorithms and keys.
