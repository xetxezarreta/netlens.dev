HTTP/3 // frames on QUIC streams

HTTP/3 keeps the semantics of HTTP but replaces TCP, TLS records and HTTP/2's frame layer with QUIC streams. Requests, responses, control messages and QPACK state each travel on a different stream. This page covers the frame format, the SETTINGS identifiers and the QPACK field section that can be decoded.

01QUIC streams

single connection · multiple streams

A QUIC connection carries independent bidirectional and unidirectional streams. A request uses a client-initiated bidirectional stream. The first bytes of a unidirectional stream declare its type: control, push, QPACK encoder or QPACK decoder. Because streams are independent, one lost packet does not block every request the way TCP head-of-line blocking does.

Frames are stream-local

An HTTP/3 frame has no stream ID in its header. The QUIC stream identifies the request. Two frames on different streams can have the same type and length while carrying unrelated meanings.

02Frames

type varint · length varint · payload

Both the frame type and the payload length are QUIC variable-length integers. The smallest encoding is one byte; larger values use two, four or eight bytes. The two most significant bits of the first byte select the width.

Unknown settings are fatal

An HTTP/3 endpoint must reject a SETTINGS frame with an unknown identifier (except reserved GREASE values). This is intentionally stricter than ignoring an unknown HTTP/1.1 header.

04QPACK

static table · dynamic table · field lines

QPACK compresses header fields with a static table of 99 common entries and a connection-local dynamic table. Unlike HPACK, QPACK is designed for out-of-order streams: a field section can reference entries that arrive later, but the stream may block until they do. The decoder on this page resolves static-table references and plain literals; dynamic and post-base references are reported and are not inferred.

07Wire notes

HTTP/3 is distinct from HTTP/2 over UDP
  • No stream IDs in frames. The QUIC stream provides identity. A frame parser that expects an HTTP/2 9-byte header will fail immediately.
  • Varints are QUIC varints. The 2-bit prefix selects 1, 2, 4 or 8 bytes. Values need not be encoded in their shortest form except where the RFC requires it.
  • SETTINGS is mandatory and must be first on the control stream. A connection that sends frames before SETTINGS is in error.
  • QPACK can block. Dynamic references may not be available yet. The blocked-streams setting bounds the damage; it does not remove it.
  • HTTP/3 does not define a reason phrase. Status is a pseudo-header value; there is no text status line.
  • 0-RTT is a QUIC feature. An HTTP/3 request can be sent in 0-RTT, but replay risk belongs to the application and the QUIC stack.
