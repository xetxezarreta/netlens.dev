Checksum & CRC laboratory // input bytes and derived checksums

Compute the checksum families used in packet headers and file formats. Internet checksum for IPv4, TCP, UDP and ICMP; CRC-32 for Ethernet and zlib; CRC-32c for SCTP and iSCSI; FNV and Adler for hash tables and zlib streams.

Paste the covered bytes with the checksum field included.

For IPv4, TCP, UDP and ICMP the one's-complement sum over the covered bytes, with the checksum included, must be 0xFFFF. The UDP checksum also covers an IP pseudo-header; paste the pseudo-header followed by the UDP datagram to verify it.

03Notes

which checksum where
  • Internet checksum is not a CRC. It is a one's-complement sum, cheap in software and weak against structured errors.
  • CRC-32 is not CRC-32c. Ethernet, PNG and zlib use the IEEE polynomial; SCTP, iSCSI and Btrfs use Castagnoli. The table and the polynomial differ.
  • FNV-1a is a hash, not an error check. It is efficient and straightforward, but it is not collision-resistant.
  • Adler-32 is used by zlib. It is weaker than CRC-32 but cheaper on some CPUs.
  • A checksum is not authentication. It can be recomputed by any party. A MAC or digital signature is required for integrity against an active attacker.
