NTPv4 // timestamps and clock synchronisation

NTP is one of the oldest protocols still in daily use. The packet is fixed at 48 bytes; the principal fields are the four 64-bit timestamps and the arithmetic that derives offset and delay. This page decodes the header, the reference identifier and the clock relationship.

01Header layout

48 bytes · all modes

The first byte packs Leap Indicator, Version and Mode. The next three bytes are stratum, poll exponent and precision. The four timestamps are Reference, Origin, Receive and Transmit. Extension fields and a MAC may follow the 48-byte header.

Origin and Transmit are not the same clock

Origin is the client's transmit timestamp echoed by the server. Receive and Transmit are the server's own receive and send times. A client uses all four to estimate offset and round-trip delay.

NTP is not authenticated by default

Symmetric key authentication and Autokey exist but are not universal. An unauthenticated NTP client trusts whatever answers first. DNS spoofing or a local attacker can shift a clock.

03Clock offset

T1 · T2 · T3 · T4

With client transmit T1, server receive T2, server transmit T3 and client receive T4, the standard estimates are:

arithmetic
offset = ((T2 − T1) + (T3 − T4)) / 2
delay  = (T4 − T1) − (T3 − T2)

This assumes the path delay is roughly symmetric. Asymmetric routing, queuing or a inaccurate or malicious server produces a biased offset. Consequently, a well-behaved client uses several servers and filters outliers.

Decoding a packet with all four timestamps displays the computed offset and delay.

06Wire notes

operational considerations
  • The epoch is 1900. Unix time starts in 1970; the difference is 2,208,988,800 seconds. A 32-bit NTP seconds field wraps in 2036.
  • The fraction is not milliseconds. It is a binary fraction: 2⁻³² of a second. Converting to decimal and back loses precision if done carelessly.
  • Kiss-o'-death is a stratum-0 packet. RATE, DENY and RSTR tell a client to back off or stop. They are not time.
  • Poll and precision are signed exponents. A precision of −20 means about one microsecond; it is not a byte count.
  • NTP compared with SNTP. SNTP uses the same packet format with a simpler client algorithm. A capture does not identify which implementation sent a packet.
  • NTS is different. Network Time Security wraps NTP in TLS for key establishment and authenticates packets; the base NTP header remains.
