ICMPv6 // NDP, SLAAC & MLD

IPv6 has no ARP and no broadcast. Neighbor Discovery replaces both with ICMPv6 messages over link-local multicast. This page covers the common header, the message types commonly encountered in a capture, the ND option TLVs and the checksum used to validate a message.

01Message layout

select a field to pin it; Escape clears the selection

Every ICMPv6 message starts with Type, Code and a 16-bit Checksum. The next 32 bits are type-specific: an echo identifier and sequence, an MTU, a pointer, or the reserved field before a target address. The checksum is computed over the IPv6 pseudo-header, the ICMPv6 header and the entire ICMPv6 body.

ICMPv6 is not ICMPv4 with a different number

The type space, the error codes and the checksum pseudo-header are different. Router Solicitation, Router Advertisement, Neighbor Solicitation, Neighbor Advertisement and Redirect live only in ICMPv6. MLD uses types 130–132 and 143.

02Types & codes

8-bit type · 8-bit code

The type determines the body layout. Error messages carry the beginning of the invoking packet for diagnosis; informational messages are usually self-contained. The code refines the meaning but does not change the body in most cases.

Type 2 is Packet Too Big, not Fragmentation Needed

ICMPv4 uses type 3 code 4 for “fragmentation needed and DF set”. IPv6 routers never fragment, so the equivalent is ICMPv6 type 2 with the next-hop MTU. Treating the two as the same breaks path-MTU discovery.

03Neighbor Discovery

RS · RA · NS · NA · Redirect

Neighbor Discovery is a set of ICMPv6 messages plus a TLV option space. A host discovers routers with RS/RA, resolves a link-layer address with NS/NA, detects duplicate addresses with DAD, and learns prefixes for stateless address autoconfiguration from Prefix Information options.

Router Advertisement in detail

The M and O flags are not “DHCP on/off”

M tells hosts to use DHCPv6 for addresses; O tells them to use DHCPv6 for other configuration such as DNS. A network can use SLAAC for addresses and DHCPv6 only for DNS. A router can also advertise both and let the host choose. Read the flags with the prefix's A and L bits, not in isolation.

04SLAAC & DAD

from prefix to usable address

Stateless Address Autoconfiguration combines an advertised prefix with an interface identifier. The host first forms a tentative address, runs Duplicate Address Detection with a Neighbor Solicitation to the solicited-node multicast address, and only then assigns the address. Privacy extensions (RFC 8981) change the interface identifier over time; they do not change the prefix.

DAD is not authenticated

Any host on the link can answer a DAD probe and block an address. First-hop security, RA Guard and ND inspection exist because Neighbor Discovery trusts the link. A clean DAD result indicates that no response was received within the detection window; it does not establish ownership of the address.

05Encoder

checksum uses the IPv6 pseudo-header

Select a message type, complete the fields and supply the IPv6 source and destination so that the checksum can be computed. Echo, RS, RA, NS, NA and the four error types have dedicated bodies. The encoder builds structurally valid bytes; it does not sign, encrypt or claim that a Neighbor Advertisement is trustworthy.

The checksum is computed over a 40-byte IPv6 pseudo-header (source, destination, 32-bit length, zeroes, Next Header 58) followed by the message. It is not an IPv4 pseudo-header.

what the checksum proves

It proves the message and pseudo-header survived the path without a bit error. It does not prove the sender, the neighbour or the prefix. ND spoofing is a separate problem.

07Wire notes

operational considerations
  • The checksum is mandatory. IPv6 has no “checksum not computed” option for ICMPv6. A zero checksum is wrong, not a wildcard.
  • Neighbor Solicitation targets a solicited-node multicast address. For 2001:db8::1, the destination is ff02::1:ff00:1; the last 24 bits come from the target address.
  • DAD probes use the unspecified source. The NS is sent from :: to the solicited-node group, with the tentative address in the Target Address field.
  • RA lifetimes are 16-bit units and a zero router lifetime means “not a default router”. It does not mean the advertisement is invalid.
  • Prefix Information L and A bits. L means on-link; A means autonomous (usable for SLAAC). A prefix can be on-link without being used for autoconfiguration.
  • MLD is ICMPv6. MLDv1 types 130–132 and MLDv2 type 143 share the ICMPv6 header. They are not IGMP with a new name.
  • ND has no authentication by default. SEND (RFC 3971) exists but is rarely deployed; RA Guard and ND inspection are operational mitigations.
