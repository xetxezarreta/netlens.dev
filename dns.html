DNS is a message protocol. The 12-byte header and four sections are shared by queries and responses; the QR bit decides which direction the message is travelling.

~/protocols/dns

DNS // RFC 1035

The Domain Name System turns names into records. Every query and response shares one header, four counted sections and a variable-length name encoding with compression pointers. DNS normally rides UDP/53, falls back to TCP for truncation and zone transfers, and is increasingly carried inside QUIC, TLS and HTTPS.

01Message layout

twelve bytes · four counted sections

A DNS message begins with a fixed 12-byte header. ID matches a response to its query; the flags word carries direction, opcode, truncation and response code; the four counts say how many entries follow in the question, answer, authority and additional sections. Everything after the header is a sequence of names, fixed fields and length-delimited RDATA.

SectionCount fieldContentsNotes
QuestionQDCOUNTQNAME, QTYPE, QCLASSNormally exactly one question. The name is not repeated with a type/class header.
AnswerANCOUNTResource recordsDirect answers, CNAME chains and DNSSEC signatures.
AuthorityNSCOUNTResource recordsDelegation NS records or the SOA that proves a negative answer.
AdditionalARCOUNTResource recordsGlue addresses, OPT (EDNS), TSIG and other supporting records.
counts are declarations, not limits

A parser must stop when the bytes run out even if the counts promise more records. Truncated messages, compression loops and bad RDLENGTH values are common in captures. The decoder below reports the first inconsistency instead of guessing.

02Flags & response codes

one 16-bit word · direction, policy and status

The flags word is dense: one direction bit, a four-bit opcode, five single-bit flags, three DNSSEC-related bits and a four-bit response code. Extended response codes live in the EDNS OPT record, so the effective RCODE can be larger than 15.

NXDOMAIN is not NODATA

NXDOMAIN means the name does not exist. NOERROR with an empty answer and an SOA in the authority section means the name exists but has no record of that type. Tools that collapse both into “not found” hide useful DNS behaviour.

03Names & compression

length-prefixed labels · 14-bit pointers

A domain name is a sequence of labels. Each label starts with a length byte (1–63), followed by that many bytes; a zero byte terminates the name. The root is a single zero byte. Total encoded length is at most 255 bytes, and a presentation-format name is at most 253 characters.

DNS compresses repeated suffixes. A length byte with its top two bits set is a pointer: the remaining 14 bits are an offset from the start of the message. A pointer terminates the current name, so a parser must jump, continue reading, and remember where it should resume after the pointer. Pointers may not point forward in practice, must stay inside the message, and must not loop.

compression is per message, not per record

The pointer target is an absolute offset from the first byte of the DNS message. A name at offset 0x0024 that points to 0xC00C means “continue at byte 12” — normally the question name. When a decoder reports a name, it should also report how many pointers it followed.

04Resource records

name · type · class · TTL · RDLENGTH · RDATA

Every answer, authority and additional entry uses the same resource-record envelope. The type decides how to interpret RDATA; RDLENGTH lets a parser skip a record even when it does not understand the type. That length-delimited design is what makes DNS extensible.

TTL is a 31-bit value

RFC 2181 restricts TTL to 31 bits; a value with the high bit set is treated as zero by many implementations. TTL is a cache lifetime in seconds, not a timestamp. Resolvers decrement it as records sit in cache.

05Transport & EDNS(0)

UDP/53 · TCP/53 · 512 B and beyond

DNS is transport-independent. Classic DNS uses a single UDP datagram per message and retries over TCP when the response sets TC. TCP carries a two-byte length prefix before each message because a TCP stream has no message boundaries. Zone transfers (AXFR, IXFR) always use TCP.

EDNS(0)

EDNS(0) adds one OPT pseudo-record in the additional section. It advertises a larger UDP payload size, carries an extended RCODE and the DNSSEC OK bit, and transports options. OPT is never cached and never appears in a zone file.

fragmentation is not free

Large UDP responses can be fragmented at the IP layer, which is lossy and sometimes filtered. Modern guidance is to advertise an EDNS payload of about 1232 bytes over IPv6 and to prefer TCP when the answer is larger. A 4096-byte advertisement is a maximum, not a promise that the path will carry it.

06Encoder

query or response · raw DNS or UDP datagram

Build a DNS message from a question and zero or more resource records. Record lines use name [ttl] TYPE data. Names may be written with or without a trailing dot; the encoder adds root termination and compresses repeated suffixes.

compression pointers are relative

The encoder reuses earlier suffixes by writing a pointer to their offset. A DNS message is therefore not self-contained per record: RDATA names can point into the question section. Re-ordering sections without rebuilding pointers breaks it.

08Wire notes

small messages, large operational surface
DNS is case-insensitive on the wire, but case is preserved

Name comparisons ignore ASCII case, yet resolvers may randomise the case of query labels (DNS 0x20 encoding) and check that the response echoes it. A canonicalising decoder should preserve the original bytes even when it compares names case-insensitively.

  • ID is not authentication. A 16-bit transaction ID plus source-port randomisation raises the cost of off-path spoofing, but DNS cookies and DNSSEC are the actual defences.
  • Compression pointers must not loop. A pointer may jump backwards but must terminate. Parsers need a jump limit and a bound check on every target offset.
  • RDLENGTH is authoritative for skipping. A parser that does not understand a type can still walk the message because RDATA is length-delimited. Never parse past RDLENGTH.
  • TC means retry over TCP. A truncated UDP response is not a complete answer. The client should repeat the query over TCP rather than guess at the missing records.
  • UDP payload size is advertised, not guaranteed. EDNS CLASS is the requestor's receive buffer. Path MTU, fragmentation and middleboxes still decide what arrives.
  • CNAME chains end at the queried type. A response may contain a CNAME and then records for the canonical target. The owner name in each record is absolute after compression resolution.
  • DNSSEC does not encrypt. RRSIG and DNSKEY prove integrity and origin for signed zones. Names and addresses remain visible unless the transport is encrypted (DoT, DoH, DoQ).
  • mDNS and LLMNR are different protocols. They use DNS message format on multicast addresses and local ports; they are not part of the global DNS hierarchy.
