01Header layout

click a field to pin it · esc clears

Sequence Number and Acknowledgment Number are 32-bit unsigned counters that wrap. Data Offset counts 32-bit words, so 5 means the 20-byte minimum; options occupy the rest up to 40 bytes. The four reserved bits must be zero.

the twelfth byte is where diagrams disagree

Data Offset (4 bits), Reserved (4 bits), then the flag octet: CWR, ECE, URG, ACK, PSH, RST, SYN, FIN. Some older diagrams split the reserved nibble into a 3-bit reserved field plus the experimental NS bit (RFC 3540). RFC 8311 deprecated NS; treat it as reserved.

CWR and ECE are ECN signals (RFC 3168). URG makes the Urgent Pointer meaningful. ACK makes Acknowledgment Number meaningful; PSH asks the receiver to deliver buffered data; RST aborts; SYN synchronizes; FIN ends the sender's byte stream.

03Options & TLVs

kind 8-bit · length includes both

Most TCP options are TLVs. Kind 0 (EOL) and 1 (NOP) are one byte and have no length. All others have a one-byte length covering kind, length and value. The whole option list is padded to a 4-byte boundary and counted by Data Offset.

TCP option TLV

Kind1 byte
Length1 byte · 2–255
data
length − 2 bytes · padded with EOL / NOP to a 4-byte boundary

EOL (0x00) and NOP (0x01) are single bytes, not TLVs. A length below 2 is malformed. The option list is limited to 40 bytes by the 4-bit Data Offset.

04Encoder

pseudo-header checksum when IPs are supplied

Build a TCP segment with a correct header checksum. Supply IPv4 source and destination addresses to compute the pseudo-header checksum; leave them blank to emit checksum 0x0000. Payload is optional and is appended after the header.

build a TCP segment

20–60 B header

The checksum covers a 12-byte pseudo-header (source, destination, zero, protocol 6, TCP length) followed by the TCP header and payload. A valid checksum is not a valid connection.

pseudo-header, not a real header

The 12 bytes of source address, destination address, zero, protocol and TCP length are never transmitted. Both ends reconstruct them from the IP layer. For IPv6 the pseudo-header is 40 bytes and uses the next-header value instead of protocol.

06Wire notes

where TCP implementations hurt
the checksum is over a fake header

Copying a TCP segment without its IP addresses makes the checksum unverifiable. This is why packet generators ask for the pseudo-header tuple. It is also why NAT devices must recompute the TCP/UDP checksum when they rewrite addresses.

  • Data Offset is words. 5 = 20 bytes, 15 = 60 bytes. A value below 5 is malformed; a value larger than the segment means the options are truncated.
  • Options are negotiated, not universal. Window Scale and SACK-permitted are normally SYN-only; timestamps are negotiated in both directions; SACK blocks appear after loss.
  • Window Scale shifts the 16-bit window. The shift is 0–14; values above 14 should be treated as 14. The scale applies to later segments, not the SYN itself.
  • MSS is not the path MTU. It is the largest TCP payload the sender can receive, normally MTU − 40. MSS 0 is invalid.
  • The urgent pointer is practically dead. URG is rarely used and interpreted inconsistently; do not design new protocols around it.
  • NS is historic. RFC 3540 defined the ECN nonce bit; RFC 8311 deprecated the nonce. Modern parsers treat the bit as reserved.
  • Flags are not authentication. Anyone can forge a RST or a SYN. TCP sequence numbers and cookies provide some resistance, not identity.
