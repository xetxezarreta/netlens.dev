SCTP // streams, chunks & CRC32c

SCTP is a message-oriented transport protocol with multiple streams, built-in multihoming and a chunked extension model. It is used by SS7-over-IP, WebRTC data channels (as a substrate in some stacks), Diameter and a few telecom and database systems. The common header is 12 bytes; everything else is chunks.

01Common header

12 bytes · every packet

Ports identify the endpoints. The Verification Tag is chosen at association setup and must match the peer's value; it protects against stale or injected packets. The Checksum is CRC-32c over the whole packet with the checksum field zeroed.

CRC-32c is not CRC-32

Ethernet uses CRC-32 (IEEE polynomial). SCTP uses CRC-32c (Castagnoli). The two produce different values for the same bytes, so a generic “CRC32” tool will report a valid SCTP checksum as invalid.

02Chunks

type · flags · length · value

A packet carries one or more chunks. Each chunk header is four bytes and the length includes the header. Chunks are padded to a four-byte boundary, but the padding is not counted in the chunk length. The receiver can process chunks independently.

Chunk length is the whole chunk

A DATA chunk with a 4-byte payload has Length 20: 4-byte chunk header + 12-byte DATA fixed fields + 4-byte payload. Confusing chunk length with payload length is a frequent SCTP parser implementation error.

06Wire notes

differences from TCP and UDP
  • Messages, not a byte stream. SCTP preserves message boundaries. A single DATA chunk or a series of fragments forms one user message.
  • Multiple streams per association. Head-of-line blocking is per stream, not per connection. Streams are independent sequences inside one association.
  • Multihoming is built in. An association can use several IP addresses; path failure does not necessarily close the association.
  • The verification tag is mandatory. It is not a checksum; it prevents packets from an old association being accepted by a new one.
  • CRC32c is stored over the packet with the checksum field zeroed. A tool that reports CRC-32 (IEEE) will disagree.
  • NAT is awkward. SCTP's multihoming and address lists do not map cleanly to NAT; SCTP over UDP encapsulation exists for this reason.
