DHCPv6 is a distinct protocol from DHCPv4. It uses UDP 546/547, a 4-byte message header, 16-bit option codes and DUIDs. DHCPv6 does not use the DHCPv4 magic cookie or BOOTP header.

DHCPv6 // addresses, prefixes & options

DHCPv6 configures IPv6 addresses and other parameters. It is a different protocol from DHCPv4: a four-byte message header, 16-bit option codes, DUIDs, IA_NA and IA_PD containers, and a relay message format. SLAAC can provide addresses without it; DHCPv6 is still common for DNS, prefixes and managed networks.

01Message layout

4 bytes + options

The first byte is the Message Type. The next three bytes are the Transaction ID, chosen by the client and echoed by the server. Everything after that is a sequence of options. Relay messages use a different header: hop count, link address and peer address, followed by options.

No magic cookie, no BOOTP header

DHCPv4 has a 236-byte BOOTP header and a 0x63825363 magic cookie. DHCPv6 has neither. A parser that expects the DHCPv4 cookie will not find it.

06Wire notes

comparison with DHCPv4
  • UDP 546/547. Clients listen on 546, servers and relays on 547. The client's source port is 546; the destination is 547.
  • Multicast first. Clients send to ff02::1:2 (all DHCP servers and relay agents) on the local link unless a unicast server address is known.
  • DUIDs are not MAC addresses. DUID-LL wraps a link-layer address, but DUID-LLT, DUID-EN and DUID-UUID exist. Treat the whole DUID as opaque identity.
  • IA_NA and IA_PD are containers. The actual addresses and prefixes live in nested IA Address / IA Prefix options. A message can carry several IAs.
  • T1 and T2 are relative timers. They are seconds from the time the client receives the message, not absolute times.
  • SLAAC and DHCPv6 can coexist. RA M/O flags decide whether the host uses DHCPv6 for addresses, other configuration, both or neither.
