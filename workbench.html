05Formats, filters & limits

what this build deliberately does not do

The workbench reads classic pcap and a practical subset of pcapng. It follows the same encapsulation chain as the protocol pages: Ethernet, VLAN, Linux SLL/SLL2, null/loopback, raw IP, IPv4/IPv6, TCP/UDP/ICMP, then DNS, DHCP, HTTP, TLS and opaque payloads.

InputSupportNotes
Classic pcapmicrosecond and nanosecond, both byte ordersGlobal header, record headers, snaplen checks.
pcapngSHB, IDB, EPB, SPB; multiple interfacesHonours if_tsresol. One section per file.
Link typesEthernet, raw IP, IPv4, IPv6, Linux SLL/SLL2, null/loopbackOther link types are shown as raw bytes with a warning.
Timestampsabsolute UTC and relative to packet 1Simple Packet Blocks have no timestamp and show “—”.
  • No decryption. TLS application data, QUIC protected packets, ESP and encrypted BGP sessions remain opaque.
  • No IP reassembly. Non-initial IPv4/IPv6 fragments have no transport header. The walk marks fragment data and stops.
  • No full TCP state machine. Follow-stream orders payload by sequence, drops exact retransmissions and shows gaps; it does not invent missing bytes.
  • Filters are a subset. This is not Wireshark display-filter syntax. Unknown fields fail with a message instead of silently matching nothing.
  • Bounded input. This build caps a capture at 20,000 packets / 50 MB and a frame at 256 KB.
  • No upload. The File API reads the capture into this tab. There is no fetch(), no backend and no account.
captures can be hostile

Treat every capture as untrusted input. Every block and record is bounds-checked, decoded strings are escaped, and parsing is bounded. Clean parsing is not a security guarantee.
