05Formats, filters & limits

what this build deliberately does not do

The workbench reads classic pcap and a practical subset of pcapng. It follows the same encapsulation chain as the protocol pages: Ethernet, VLAN, Linux SLL/SLL2, null/loopback, raw IP, IPv4/IPv6, TCP/UDP/ICMP, then DNS, DHCP, HTTP, TLS and opaque payloads.

InputSupportNotes
Classic pcapmicrosecond and nanosecond, both byte ordersGlobal header, record headers, snaplen checks.
pcapngSHB, IDB, EPB, SPB; multiple sections and interfacesHonours if_tsresol; parses DSB, NRB and ISB blocks.
Link typesEthernet, raw IP, IPv4, IPv6, Linux SLL/SLL2, null/loopback, Radiotap/802.11, PPPoE, MPLS, VXLAN/Geneve, SCTPOther link types are shown as raw bytes with a warning.
Timestampsabsolute UTC and relative to packet 1Simple Packet Blocks have no timestamp and show “—”.
  • TLS 1.3 decryption needs a key log. Paste an SSLKEYLOGFILE or import pcapng decryption secrets. Without keys, application data, QUIC protected packets and ESP remain opaque. TLS 1.2 key-log decryption is not implemented.
  • IPv4 and IPv6 fragments are reassembled. Overlaps use first-fragment-wins and incomplete sets are reported. A reassembled datagram is attributed to the frame that completed it.
  • TCP state is best-effort. Sequence tracking, retransmission/out-of-order/zero-window/RST detection and stream reassembly are implemented. Missing bytes are marked as gaps, never invented.
  • Filters are a documented subset. This is not Wireshark display-filter syntax. It supports byte slices (frame[0:4]), contains, flow fields and tcp.analysis.*; unknown fields fail with a message.
  • Bounded input. This build caps a capture at 250,000 packets / 500 MB and a frame at 256 KB.
  • No upload. The File API reads the capture into this tab. There is no fetch(), no backend and no account.
captures can be hostile

Treat every capture as untrusted input. Every block and record is bounds-checked, decoded strings are escaped, and parsing is bounded. Clean parsing is not a security guarantee.
