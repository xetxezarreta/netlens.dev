LLDP is an Ethernet frame with EtherType 0x88CC. It is one-way, link-local and has no request/response exchange. A neighbour only advertises.

LLDP // neighbour advertisements

LLDP informs directly connected devices of the local identity: chassis ID, port ID, system name, capabilities and, optionally, management addresses, VLANs, power and related attributes. It is the protocol behind the neighbour table on a switch and the topology view in a network manager.

01TLV layout

7-bit type · 9-bit length

An LLDP frame carries a sequence of TLVs. Each TLV header is two bytes: a 7-bit type and a 9-bit length. The length counts the value only. The first three TLVs are mandatory (chassis, port, TTL) and an End TLV closes the sequence.

LLDP is not a routing protocol

It has no request, no acknowledgement and no path computation. It advertises local information to the link. A missing neighbour means the peer is not sending, the frame is filtered, or the destination MAC is blocked.

06Wire notes

operational considerations
  • The destination is a reserved multicast MAC. 01:80:c2:00:00:0e is not forwarded by bridges, so LLDP stays link-local.
  • TTL is the neighbour lifetime. The receiver expires the entry when it has not heard a new advertisement for the TTL. Zero means “shutdown” in LLDP-MED contexts.
  • Chassis ID is not always a MAC. It can be a component name, interface alias, network address or locally assigned identifier. Normalise it only for display.
  • Organizationally Specific TLVs are vendor space. 802.1, 802.3 and LLDP-MED define several; unknown OUIs should be shown as opaque bytes.
  • LLDP is not LLDP-MED. LLDP-MED extends LLDP with voice, inventory and location TLVs. A phone may send both.
  • LLDP is unauthenticated and can be spoofed. A topology map derived from LLDP is only as trustworthy as the access ports providing the advertisements.
