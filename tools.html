01Internet checksum

RFC 1071 · one's complement

The IPv4, TCP, UDP and ICMP checksum is a 16-bit one's-complement sum. To compute a header checksum, zero the checksum field first, sum the 16-bit words, fold the carries, then complement the result. The same routine verifies a finished header: the sum over everything should be 0xffff.

compute / verify

big-endian words
—

Offset is zero-based. The field is two bytes. “Zero field” clears those bytes in the input so the next compute shows the expected checksum.

checksum offload lies

A capture taken on the sending host may show a bogus checksum because the NIC computes it after the capture point. Validate on the receiving side or disable offload on the capture interface.

03Generic TLV parser

type · length · value

A generic type-length-value walker with selectable length width. Useful for options, capability lists and other byte-aligned TLVs. It does not know about TCP's one-byte EOL/NOP exceptions or IPv4's class/copied bits; those have dedicated pages.
