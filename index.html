    the diagram and the bytes should agree

    [0x00]

    Offsets are explicit

    Every block is labelled with its absolute bit range and octet offset. No “somewhere in the first word” diagrams.

    [rfc]

    Citations, not folklore

    Field definitions point at the RFC section that defines them, including the updates that changed them.

    [hex]

    Encoders that validate

    Ranges, reserved bits and lengths are checked before you paste bytes into a lab device. Decoders explain what broke.

    [tcp]

    Flags in context

    Toggle SYN, ACK, SACK and the rest. See the raw octet, tcpdump notation and the scan recipes that abuse them.

    [tlv]

    Variable fields handled

    Options, path attributes and QUIC frames are decoded as TLVs, with per-item lengths, padding and truncation warnings.

    [off]

    Static by design

    Plain HTML, CSS and JavaScript. No build step, no telemetry, no CDN. Open it from a laptop on an isolated network.

    // reading the diagrams

    One convention, everywhere.

    full conventions ->

    bit 0 is the MSB

    Diagrams are drawn left-to-right, most-significant bit first, in network byte order. A field labelled bits 0–3 occupies the top four bits of the first octet. Offsets count from the first byte of the structure being described, not from the start of the frame. WireGuard is the one little-endian exception, and it is called out on every field that needs it.
