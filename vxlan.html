VXLAN & Geneve // L2 over UDP

VXLAN stretches a layer-2 segment across a routed IP fabric. It wraps an entire Ethernet frame in UDP, adds a 24-bit VNI and lets the underlay route between VTEPs. Geneve provides a more extensible alternative: the same overlay model with a different header and a TLV option space.

01VXLAN header

8 bytes · UDP 4789

The first byte carries the I bit, which marks a valid VNI. The next 24 bits are reserved. The VNI is three bytes. The final byte is reserved. Everything after the header is a complete inner Ethernet frame, including its destination and source MAC addresses.

The VNI is not a VLAN ID

A 12-bit 802.1Q VLAN ID and a 24-bit VXLAN VNI are different namespaces. A frame can carry both. Mapping between them is a local policy decision at the VTEP, not something the VXLAN header encodes.

02Geneve

8 B base + 4-byte option units

Geneve keeps the VNI but adds a version, an option length, OAM and critical bits, and a protocol type. Options are TLVs in four-byte units. The same OUI/type/length discipline as other TLV protocols applies; unknown critical options must be rejected, unknown non-critical options can be ignored.

03Overlay path

outer underlay · inner tenant frame

The outer Ethernet/IP/UDP headers are visible to the underlay. The inner Ethernet frame is the frame presented to the tenant. A capture on the underlay shows both; a capture on a tenant interface shows only the inner frame. Consequently, VXLAN presents a layer-2 link to the guest while the physical path is routed at layer 3.

VXLAN is not encrypted

It provides segmentation and encapsulation. Confidentiality requires IPsec, MACsec or another layer. The VNI is visible on the wire and is not a secret.

06Wire notes

operational considerations
  • UDP 4789 is the IANA port. Some early implementations used 8472; the default in most modern stacks is 4789. Check both in a capture.
  • The inner frame keeps its FCS? Usually not. VXLAN carries the frame without the original Ethernet FCS; the outer transport has its own integrity checks.
  • MTU includes the overlay. VXLAN adds 50 bytes for IPv4 and 70 for IPv6 before the inner frame. A 1500-byte inner frame will not fit a 1500-byte underlay.
  • Learning is control-plane dependent. VXLAN itself has no control protocol. Flood-and-learn, EVPN or a controller supplies the MAC/VNI-to-VTEP mapping.
  • ECMP and entropy. The outer UDP source port is often derived from the inner flow to give the underlay more entropy. A fixed source port flattens ECMP.
  • Geneve options are not free. Every option adds bytes and parsing risk. Unknown critical options must cause the packet to be dropped.
