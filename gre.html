GRE // generic encapsulation

GRE encapsulates one network-layer protocol within another. It is widely used for IP-in-IP tunnels, PPTP, some SD-WAN overlays, ERSPAN and experimental topologies. The base header is short; the optional fields determine the full header length and are therefore significant in capture analysis.

01Header layout

optional fields follow the flags

The first two octets are flags and version. The next two are the Protocol Type, which describes the inner payload. If C or R is set, a checksum and reserved word follow; if K is set, a 32-bit key follows; if S is set, a 32-bit sequence number follows. Version 0 is GRE; version 1 is the PPTP variant with a different optional-field layout.

The header is not self-describing

The flags must be read to determine whether the next four bytes are a checksum and reserved pair, a key, or a sequence number. A parser that assumes a fixed four-byte header will misplace the payload.

GRE is not encrypted

GRE provides encapsulation, not confidentiality or authentication. IPsec or another layer must protect it if the path is untrusted. A GRE key is an identifier, not a secret.

03Inner payload

what the tunnel carries

The outer IP header routes the packet between tunnel endpoints. The GRE header identifies the payload. The inner packet is untouched by GRE; its TTL, addresses and checksums belong to the inner network. Recursive tunnels can exceed the MTU and cause fragmentation or PMTUD black holes.

06Wire notes

tunnel failure modes
  • MTU is the classic problem. GRE adds at least four bytes, more with key/sequence; encapsulation inside IPv4 or IPv6 adds another outer header. Inner DF can create PMTUD black holes.
  • Checksum is optional and often absent. When present, it covers the GRE header and payload, with the checksum field zeroed. A bad checksum may be silently ignored by some implementations.
  • The key is not a cryptographic key. It identifies a tunnel or flow. It does not authenticate the sender.
  • Sequence numbers are per tunnel direction. They can help reorder detection, but GRE does not retransmit.
  • PPTP is version 1. The same protocol number carries a different header. Do not decode PPTP GRE as RFC 2784 GRE.
  • GRE and IPsec. GRE over IPsec is common; the outer ESP protects the GRE header and inner packet. Without keys the capture shows only ESP.
